# 数据与题库说明

## 数据目录

- SQLite 数据库：`data/exam-paper.db`
- 单文件导入：`data/uploads`
- 目录导入：`data/imports`

不要手动删除 `data/exam-paper.db`，否则账号、试卷进度、错题库和疑问库都会丢失。

## SQLite 持久化

项目使用 `modernc.org/sqlite`，这是纯 Go SQLite 驱动，不依赖 CGO。

数据库连接使用单连接模式，减少 SQLite 写入时锁冲突：

- `SetMaxOpenConns(1)`
- `SetMaxIdleConns(1)`
- `PRAGMA busy_timeout = 8000`
- `PRAGMA journal_mode = WAL`
- `PRAGMA wal_autocheckpoint = 256`
- `PRAGMA journal_size_limit = 1048576`

启动同步题库后会执行 WAL checkpoint，避免 WAL 文件长期膨胀。

## 主要数据表

- `users`：账号。
- `exams`：试卷和进度。
- `answers`：答题记录。
- `wrong_book`：用户错题库，包含错误次数和答对次数。
- `doubt_marks`：用户疑问标记。
- `question_sources`：题库来源元信息。
- `questions`：持久化后的题目内容。

## 题库来源规则

系统会扫描项目目录下的 `.pdf` 和 `.docx` 文件，并在左侧“选择题库来源”区域显示。

- 工作目录中的题库文件会按真实目录结构显示为树形结构。
- 点击“导入目录”上传的文件会保存到 `data/imports`，界面上会按导入目录原本的树形结构显示。
- 点击“导入 PDF / DOCX”导入的散文件会保存到 `data/uploads`，界面上统一显示在“导入文件”区域。

## 启动同步题库

项目启动时会同步这两个目录到 SQLite：

- `演出协会官方题库题目`
- `演出协会模拟考`

同步时会根据文件大小和修改时间判断是否需要重新解析。若文件未变化，会直接复用数据库中的题目并放入内存缓存。

如果原始题库目录后续被删除，只要数据库中已经同步过，系统仍然可以从 `question_sources` 和 `questions` 加载题库树并生成试卷。
