# 项目结构说明

后端按照 `gin-pathway` 风格拆分，入口、路由、控制器、业务服务、数据访问和工具函数分别放在不同目录。

```text
cmd/
└── main.go                    # 程序入口，读取启动参数并启动应用
configs/                       # 配置文件目录，当前预留
docs/                          # 中文文档
internal/
├── api/                       # Gin 路由注册
├── app/                       # 应用装配、初始化数据库和题库服务
├── controller/                # HTTP 控制器，处理 API、导入和静态资源
├── middleware/                # 中间件目录，当前预留
├── model/                     # 接口和业务数据结构
├── repository/                # SQLite 数据访问层
├── service/                   # 业务服务
│   ├── parser/                # PDF/DOCX 解析服务
│   └── questionbank/          # 题库缓存、题库同步、题目查询
└── utils/                     # ID、JSON、来源清洗、选项比较等工具函数
scripts/                       # 脚本目录，当前预留
static/                        # 前端静态资源
tests/                         # 单元测试
```

## 后端分层

- `cmd/main.go`：只负责读取 `--host`、`--port` 参数并启动应用。
- `internal/app`：创建数据库连接、初始化题库服务、同步内置题库、注册 Gin 路由。
- `internal/api`：集中注册所有 HTTP 路由，保持接口路径稳定。
- `internal/controller`：处理请求参数、返回 JSON、文件上传、静态资源访问。
- `internal/service/questionbank`：负责题库缓存、启动同步、按来源加载题目、按 ID 查题。
- `internal/service/parser`：负责 PDF/DOCX 文本提取和题目解析。
- `internal/repository`：负责 SQLite 表结构、账号、试卷、答题记录、错题、疑问题和题库持久化。
- `internal/model`：统一存放接口响应和业务模型。
- `internal/utils`：统一存放通用工具函数。

## 前端结构

- `static/index.html`：页面结构和脚本加载顺序。
- `static/styles.css`：CSS 入口，只负责引入拆分后的样式文件。
- `static/css/`：基础样式、布局、题库树、刷题区、错题区和响应式样式。
- `static/js/`：状态管理、接口请求、账号、题库、组卷答题、错题和事件绑定。
